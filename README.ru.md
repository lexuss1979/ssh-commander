# ssh-commander

[English](README.md) · **Русский**

## Твой личный AI DevOps

**Поможет запустить проект на VPS и разобраться, если что-то сломалось.** Не нужно сначала становиться системным администратором.

Опиши задачу. AI-агент ssh-commander подключается к твоему серверу по SSH, сам ищет причины проблем, проводит аудит и выполняет исправления **с твоего разрешения**. Первый VPS или несколько серверов с проектами: рядом помощник, который работает на самом сервере, а не только советует, что попробовать.

**Приложение бесплатное, с открытым кодом. Подписки на ssh-commander нет.** Отдельно оплачиваются серверы и использование AI API по твоему ключу.

[![От new-vps до работающего сайта: агент устанавливает Nginx, настраивает сайт и проверяет HTTP 200](docs/media/hero-new-vps.gif)](docs/media/hero-new-vps.mp4)

**Новый сервер. Одна просьба. Работающий сайт.** Агент устанавливает Nginx, создаёт страницу и проверяет результат. Ты подтверждаешь изменения и открываешь сайт. [Смотреть пример (MP4, 45 с)](docs/media/hero-new-vps.mp4). Записано на чистом тестовом SSH-сервере; ожидание и промежуточные шаги сокращены.

> [!TIP]
> **Сначала попробуй без AI.** Терминал, файлы и Docker работают без API-ключа. Познакомься с приложением, а агента подключи в **«Настройках»**, когда будешь готов.
>
> Для работы с сервером SSH-доступ нужен сразу. AI подключается отдельно: агент использует права выбранного SSH-пользователя и спрашивает разрешение перед изменениями.

## Приходи с проблемой, а не с пачкой логов

В отдельном чате ты часто работаешь посредником: копируешь ошибку, получаешь команду, выполняешь, отправляешь вывод, повторяешь. Здесь агент может исследовать сервер сам: читать логи, проверять службы и контейнеры, искать причину по полученным данным и предлагать исправление.

Начни с задачи обычными словами:

- **Первый VPS:** «Я арендовал сервер. Посмотри, что на нём установлено, и помоги запустить моё приложение».
- **Что-то сломалось:** «Сайт перестал отвечать. Найди причину и предложи исправление».
- **Нужен свежий взгляд:** «Проведи аудит безопасности сервера и объясни, что требует внимания. Пока ничего не меняй».

Не нужно заранее знать, какую команду выполнить, чтобы получить помощь. Агент берёт на себя исследование, а ты проверяешь предложенные изменения. Терминал, файлы и Docker Explorer остаются под рукой: в любой момент можно продолжить работу самостоятельно.

**Закончилось место на диске?** Агент сам исследует сервер, находит большой лог, спрашивает разрешение на очистку и проверяет результат. [Смотреть пример диагностики (MP4, 26 с)](docs/media/hero-disk-full.mp4).

## Один VPS или несколько

Собери серверы своих проектов в одном приложении. У агента есть отдельная память для каждого сервера, а к одному диалогу можно подключить несколько серверов для общей задачи. Мониторинг и пороговые алерты помогают заметить проблему; попроси агента разобраться, когда нужна помощь.

Это интерактивный помощник, а не автономный дежурный 24/7. Агент может ошибаться: проверяй команды перед подтверждением и сохраняй резервные копии.

## Быстрый старт

Запускай ssh-commander **на своём компьютере**: нужны Git и Docker с Compose v2. Подключи к нему уже арендованный Linux VPS; само приложение серверы не арендует.

```bash
git clone https://github.com/lexuss1979/ssh-commander.git
cd ssh-commander
docker compose up -d --build
```

Открой [http://localhost:8080](http://localhost:8080), задай пароль приложения и добавь API-ключ своего AI-провайдера. Укажи SSH-адрес сервера и данные для входа, затем попроси агента проверить его состояние. Файл `.env` не нужен. Ключ AI можно пропустить: терминал, файлы и другие ручные инструменты работают и без агента.

**Пошагово:** [первый сервер и первая задача](docs/getting-started.ru.md) — подключение по SSH, настройка AI, подтверждение действий и решение типичных проблем.

[![Быстрый старт: клонирование, сборка Docker, настройка и работающий SSH-терминал](docs/media/quickstart.gif)](docs/media/quickstart.mp4)

[Смотреть быстрый старт (MP4, 37 с)](docs/media/quickstart.mp4). В ролике ключ AI пропущен, подключение идёт к тестовому серверу; для работы агента добавь свой ключ в «Настройках».

Пароль, провайдер, ключ и модель AI затем меняются в **«Настройках»** (шестерёнка внизу сайдбара), без перезапуска. Конфигурация хранится в `data/settings.json`.

Для настройки через окружение скопируй `.env.example` в `.env` **до первого запуска** и отредактируй его. Замени пример `APP_PASSWORD=change-me` своим паролем или оставь значение пустым для настройки через интерфейс. `APP_PASSWORD` и `AI_API_KEY`/`AI_API_BASE`/`AI_MODEL` только задают начальные настройки; после первого запуска изменение этих переменных не действует.

SSH-ключи можно положить в `keys/` или импортировать через форму сервера («Импортировать…», сохранение с правами `0600`). В профиле укажи путь внутри контейнера, например `/keys/id_rsa`.

> Собирать фронтенд вручную не нужно — Dockerfile собирает его внутри образа.
> Если в браузере появляется «Cannot GET /», значит контейнер запущен со старой
> версией образа: выполни `docker compose up -d --build` ещё раз (флаг `--build`
> обязателен после изменения кода).

## Стоимость и данные

Приложение бесплатно по лицензии MIT. Использование AI оплачивается отдельно выбранному провайдеру: стоимость зависит от модели и задачи, приложение ведёт учёт примерных расходов. Поддерживаются OpenAI-совместимые провайдеры и собственный сервер модели.

ssh-commander работает локально, защищён паролем и слушает только `127.0.0.1`. Нет аккаунта ssh-commander и телеметрии. Состояние приложения хранится на твоём компьютере, но **запросы AI и результаты инструментов передаются выбранному провайдеру**. Не открывай приложение в интернет; перед использованием прочитай раздел [«Безопасность»](#безопасность).

## Возможности

- **Терминал** — полноценный PTY через xterm.js; сессия переживает перезагрузку вкладки; кнопка «Обновить сессию» переустанавливает SSH-подключение (применяет новые группы и права).
- **Файловый менеджер** — просмотр, загрузка/скачивание, редактирование, создание, переименование, удаление, chmod (SFTP).
- **Docker Explorer** — контейнеры, образы, volumes, сети; запуск, остановка, рестарт, удаление, pull, run, live-логи (docker CLI по SSH).
- **AI-агент** — OpenAI-совместимый API с tool calling. Команды чтения выполняются автоматически, изменения (запись файлов, запуск/удаление контейнеров, любые небезопасные команды) — только после подтверждения в интерфейсе. Для каждого профиля ведёт `MEMORY.md` (важные находки из прошлых сессий, автозагрузка в контекст при старте).
- **Несколько серверов** — профили SSH с паролем или ключом.
- **Интерфейс** — русский и английский языки, тёмная и светлая темы. Переключение в «Настройки» → «Интерфейс» (шестерёнка внизу сайдбара), без перезагрузки; язык агента совпадает с языком интерфейса.

## Конфигурация

Переменные окружения задаются через `.env` (шаблон — `.env.example`); внутри контейнера — через `environment` в `docker-compose.yml`.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `APP_PORT` / `APP_HOST` | `8080` / `127.0.0.1` | Порт и адрес HTTP/WS сервера. Дефолт петлевой; внутри контейнера образ сам ставит `0.0.0.0`, чтобы работала публикация порта. При не-петлевом адресе сервер печатает предупреждение |
| `APP_PASSWORD` | пусто | Пароль веб-интерфейса. **Только seed при первом старте**: копируется хешем в `data/settings.json`; пусто — задаётся в onboarding. После первого старта env не читается; смена в «Настройки» → «Безопасность» |
| `DATA_DIR` | `/data` (docker) | Каталог с `settings.json`, `profiles.json`, `db-connections.json`, `ai-dialogues.json`, `memory/` и т.п. |
| `KEYS_DIR` | `/keys` (docker) | Каталог с SSH-ключами |
| `WEB_DIST` | авто-определение | Путь к собранному фронтенду |
| `AI_API_BASE` | `https://api.deepseek.com/v1` | Базовый URL OpenAI-совместимого API. **Только seed при первом старте** (вместе с ключом определяет пресет провайдера); дальше — `data/settings.json` |
| `AI_API_KEY` | — | Ключ API; без него (ни в settings, ни в seed) агент недоступен. **Только seed при первом старте**; дальше — `data/settings.json` |
| `AI_MODEL` | `deepseek-v4-flash` | Модель агента. **Только seed при первом старте**; дальше — `data/settings.json` |
| `AI_MAX_STEPS` | `30` | Лимит шагов агента |
| `AI_TEMPERATURE` | `0.2` | Температура модели |
| `AI_SEARCH_API_BASE` | пусто | Anthropic-совместимая база веб-поиска (env-only). У пресета DeepSeek поиск включён из коробки — тот же ключ, env не нужен; переменная для остальных провайдеров (например, «чат OpenAI + поиск DeepSeek»). Пусто и не DeepSeek — поиск выключен, инструмент `web_search` модели не объявляется |
| `AI_SEARCH_MODEL` | `deepseek-v4-flash` | Модель для веб-поиска (серверный инструмент `web_search_20260209`) |
| `TUNNEL_PORT_MIN` / `TUNNEL_PORT_MAX` | `10000` / `10049` | Диапазон портов для SSH-туннелей (локальный конец) |

Профили серверов хранятся в `data/profiles.json` (volume `./data`), диалоги агента — в `data/ai-dialogues.json`, память агента — в `data/memory/<profileId>/MEMORY.md`; конфигурация приложения (хеш пароля, провайдер/ключ/base/модель AI) — в `data/settings.json`, единственном источнике правды в рантайме. Ключи монтируются из `./keys` в `/keys` внутри контейнера. В профиле путь к ключу указывается как путь внутри контейнера, например `/keys/id_rsa`. Ключ можно импортировать прямо из веб-интерфейса (форма сервера → «Импортировать…») — он сохраняется в `./keys` с правами `0600`; содержимое ключей через API не отдаётся, а путь к ключу в профиле обязан лежать внутри этого каталога. Отпечатки ключей хостов — в `data/known-hosts.json`. Все файлы в `data/` пишутся с правами `0600`, старым файлам права чинятся при старте.

## Безопасность

- Сервис публикуется только на `127.0.0.1` — недоступен из сети.
- Вход по паролю (scrypt-хеш в `data/settings.json`), httpOnly cookie, rate-limit попыток логина.
- Ключ SSH-хоста проверяется по модели «доверие при первом подключении», как в `ssh(1)`: первый ключ запоминается в `data/known-hosts.json`, изменившийся обрывает подключение — пароль не уходит тому, кто ответил вместо сервера.
- Запросы с постороннего источника отклоняются и на API, и на рукопожатии WebSocket: страница в соседней вкладке не сможет управлять вашим терминалом.
- Секреты профилей не возвращаются в браузер: сохранённый пароль показывается как «задан», пустое поле означает «не менять».
- Бэкап профилей содержит пароли SSH и сами приватные ключи, поэтому экспорт с секретами **требует пароль шифрования**; без него выгружается бэкап без секретов.
- AI-агент не выполняет мутирующие действия без подтверждения; автоматические read-only команды проходят через **allow-лист** (только читающие утилиты — без интерпретаторов и сетевых клиентов; конвейеры, редиректы и подстановки запрещены). Чтение файла, похожего на хранилище секретов (`.env`, приватные ключи, `.pgpass`), тоже спрашивает подтверждение.
- Значения секретов **вырезаются из вывода инструментов** до того, как он попадёт модели, в интерфейс и в `data/ai-dialogues.json`: PEM-ключи, пары `ИМЯ=значение` с говорящим именем, токены известного вида, пароли в URL и все значения `Env` в `docker inspect`. Тот же фильтр стоит на `write_memory`, поэтому секреты не попадают и в `MEMORY.md` — это обеспечено кодом, а не только запретом в промпте. Редакция работает по шаблонам: это страховка, а не гарантия.
- Пароли SSH и passphrase ключей хранятся открытым текстом в `data/profiles.json` — это локальный однопользовательский инструмент, не выкладывайте volume наружу.
- Веб-поиск отправляет текст запросов во внешний поисковый API. У пресета DeepSeek он включён автоматически, у остальных только при заданном `AI_SEARCH_API_BASE`. Чтобы отключить поиск, выберите другой пресет и оставьте эту переменную пустой.

## Разработка

```bash
# сервер (порт 8080)
cd server && npm install && npm run dev

# фронтенд с hot-reload (порт 5173, проксирует /api и /ws на 8080)
cd web && npm install && npm run dev
```

Тесты сервера: `cd server && npm test`.
