# Первый сервер и первая задача

[English](getting-started.md) · **Русский** · [README](../README.ru.md)

Этот путь подходит для первого знакомства: подключить Linux-сервер, дать агенту проверить его состояние и затем перейти к своей задаче. Для экспериментов используй тестовый сервер; перед изменениями важных данных сделай резервную копию.

## 1. Запусти приложение

Нужны запущенный Docker с Compose v2 и Linux-сервер с SSH-доступом. ssh-commander запускается **на твоём компьютере**, а не на VPS. Git и Node/npm не нужны; само приложение серверы не арендует. Создай пустую папку и скачай Compose версии `0.1.1`:

Linux/macOS:

```bash
mkdir ssh-commander
cd ssh-commander
curl --fail --location https://raw.githubusercontent.com/lexuss1979/ssh-commander/v0.1.1/docker-compose.release.yml --output compose.yaml
docker compose up -d
```

Windows PowerShell:

```powershell
New-Item -ItemType Directory ssh-commander
Set-Location ssh-commander
Invoke-WebRequest -UseBasicParsing -Uri 'https://raw.githubusercontent.com/lexuss1979/ssh-commander/v0.1.1/docker-compose.release.yml' -OutFile compose.yaml
docker compose up -d
```

[Бэкапы, обновление и сборка из исходников](installation.md).

Открой [http://localhost:8080](http://localhost:8080). При первом запуске задай пароль длиной не менее 8 символов и повтори его. API-ключ пока можно пропустить. Нажми **«Завершить настройку»**. Файл `.env` для этого пути не нужен.

Не путай данные доступа: **пароль приложения** защищает локальную панель; **пароль или ключ SSH** даёт доступ к серверу; **API-ключ** позволяет обращаться к AI-провайдеру. Это три разные вещи.

## 2. Подключи сервер

Открой **«Управление серверами» → «+ Новый сервер»**. Это обычная форма подключения. Отдельная кнопка **«Новый сервер (root + пароль)…»** запускает настройку SSH-ключа и может отключить парольный вход; для этого руководства она не нужна.

| Поле | Что указать |
|---|---|
| Имя | Удобное имя, например `new-vps`. Оно не меняет hostname сервера. |
| Хост | IP-адрес или имя сервера от провайдера, без `http://`, пути и порта. |
| Порт | SSH-порт, обычно `22`; используй значение провайдера. |
| Пользователь | Существующий SSH-пользователь. Не оставляй `root` только потому, что он подставлен в форме. |
| Аутентификация | «Пароль» или «SSH-ключ», в зависимости от настроенного доступа. |

При входе по паролю укажи **пароль пользователя сервера**. При входе по ключу выбери **«SSH-ключ» → «Импортировать…»**, укажи файл приватного ключа, не `.pub`. Если ключ защищён, заполни **«Passphrase ключа (если задана)»**. Импортированный ключ сохранится локально в `keys/`; путь в форме будет вида `/keys/id_ed25519`.

Нажми **«Проверить подключение»**. При успехе увидишь результат и отпечаток ключа хоста. Первый ключ запоминается автоматически; по возможности сверь отпечаток через доверенную консоль провайдера. Затем нажми **«Сохранить»**, закрой окно и выбери `new-vps` в сайдбаре. Во вкладке **«Терминал»** можно проверить, что открывается командная строка сервера.

Для удалённого VPS не указывай `localhost` или `127.0.0.1`: при Docker-запуске это адрес самого контейнера приложения, а не твоего VPS. Docker на удалённом сервере не нужен для обычного SSH-подключения.

## 3. Настрой AI

Если ключ ещё не задан, открой шестерёнку внизу сайдбара: **«Настройки» → «AI-агент»**. Выбери провайдера, введи его API-ключ и доступную этому ключу модель. Для **«Свой URL»** также нужен Base URL OpenAI-совместимого API. Нажми **«Сохранить»**; перезапуск приложения не требуется.

Без ключа терминал и другие ручные инструменты работают, агент недоступен. API оплачивается отдельно по условиям провайдера. Примерные расходы видны в диалоге и в **«Настройки» → «ИИ-расходы»**. Язык интерфейса и агента меняется в **«Настройки» → «Интерфейс»**.

Ключ вводи только в настройках, не в диалоге. Запросы и результаты инструментов передаются выбранному AI-провайдеру; не отправляй агенту пароли или приватные ключи. Подробнее: [стоимость и данные](../README.ru.md#стоимость-и-данные), [безопасность](../README.ru.md#безопасность).

## 4. Дай первую задачу

Убедись, что выбран нужный сервер. Открой панель кнопкой **«AI-агент»**, если она скрыта, и отправь:

> Посмотри состояние этого сервера: какая ОС, сколько свободного места, какие службы и порты активны. Кратко объясни, что требует внимания. Пока ничего не устанавливай, не перезапускай и не меняй.

Агент начнёт проверку. Разрешённые инструменты чтения выполняются автоматически. Для других действий у поля ввода появляется панель подтверждения:

- **«Подробнее»** раскрывает аргументы, например полную команду или содержимое файла. Проверь также, на каком сервере выполняется действие.
- **«Подтвердить»** разрешает конкретное действие. Если оно непонятно или не соответствует задаче, нажми **«Отклонить»** и попроси объяснить или предложить другой вариант.
- **«Стоп»** прерывает работу агента, но не откатывает изменения. Уже запущенная удалённая команда может продолжить выполнение.

Подтверждение иногда требуется и для проверки, например HTTP-запроса: автоматический режим чтения намеренно ограничен. Сам факт появления кнопки не означает, что действие безопасно.

## 5. Перейди к своей задаче

[Скриншот подтверждения](media/agent-approval.png) · [Обзор сервера](media/server-overview.png). Настоящий интерфейс, вымышленный SSH-профиль и локальный сценарный ответ AI; [условия съёмки](media/README.md).

Для нового тестового VPS можно включить переключатель **«План»** и написать:

> Хочу простой сайт «Hello from my VPS» на Nginx, доступный по публичному IP этого сервера через HTTP. Сначала проверь, свободен ли порт 80 и нет ли существующего сайта. Если есть, ничего не заменяй и спроси меня. Предложи план установки, проверки и отката. Настройки SSH не меняй; изменения firewall согласуй отдельно.

Прочитай план. Кнопка **«Выполнить»** запускает работу по нему, но отдельные изменения всё равно потребуют подтверждения. После выполнения попроси агента проверить конфигурацию, получить HTTP-ответ и дать адрес сайта. Открой этот адрес в своём браузере: успешной проверки внутри сервера недостаточно, чтобы доказать доступность снаружи.

Для сайта на удалённом VPS используй его публичный адрес, не `localhost`. Если сайт не открывается, напиши агенту, какой адрес проверял и какую ошибку видишь. Попроси проверить службу, адрес прослушивания и firewall; правила сети в панели VPS-провайдера могут потребовать твоего участия. Не отключай защиту целиком ради проверки.

[Посмотреть пример с Nginx (45 секунд)](media/hero-new-vps.mp4). В ролике используется локальный тестовый SSH-сервер и порт `8088`, поэтому его адрес нельзя переносить на свой VPS буквально.

## Если что-то не получилось

| Симптом | Что проверить |
|---|---|
| Панель на `localhost:8080` не открывается | Docker запущен? В каталоге проекта выполни `docker compose ps`, затем `docker compose logs --tail=100`. Ошибка занятого порта означает, что его уже использует другой процесс; не останавливай незнакомые сервисы вслепую. |
| SSH: timeout / connection refused | Хост, SSH-порт, состояние сервера, VPN и сетевые правила провайдера. Агент не сможет исследовать сервер, пока само SSH-подключение не работает; используй консоль провайдера. |
| SSH: authentication failed / permission denied | Имя пользователя, выбранный способ входа, пароль либо приватный ключ и его passphrase. Пароль панели не является паролем SSH. |
| Ключ хоста изменился | Остановись и проверь причину через доверенную консоль провайдера. Это может быть переустановка или подмена сервера. Не удаляй запись доверия просто ради подключения. |
| Агент недоступен, ошибка API | В «Настройки» → «AI-агент» проверь провайдера, ключ, модель и Base URL. Для 401/403 проверь доступ ключа; для 429 — лимиты и баланс у провайдера. Не публикуй ключ вместе с ошибкой. |
| Нет прав на действие на сервере | Агент действует с правами SSH-пользователя. Попроси объяснить необходимые права; не отправляй sudo-пароль текстом в чат и не меняй всё на `root` без понимания причины. |

Если проблема остаётся, [создай issue](https://github.com/lexuss1979/ssh-commander/issues): укажи версию, ОС своего компьютера, способ запуска, шаги и текст ошибки. Перед отправкой убери секреты и приватные данные из логов и скриншотов.
