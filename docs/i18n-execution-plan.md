# План исполнения локализации (i18n runbook) — как делаем и как проверяем

> Исполнительный runbook к стратегическому плану `docs/i18n-plan.md`
> (решения «что делаем / что не делаем» приняты там и здесь не
> пересматриваются). Этот документ отвечает на вопросы: в каком порядке
> выносим строки, по каким правилам, какими коммитами и как проверяем
> каждый шаг и результат целиком.
>
> Статус: план. Реализация — в ветке `i18n` (см. §1), этот документ
> лежит в `i18n-execution-plan`.

## 1. Ветвление и коммиты

- Работа — в ветке `i18n` от `main`. Этот план закоммичен отдельно в
  `i18n-execution-plan` и вливается в `i18n` первым коммитом
  (`git merge i18n-execution-plan` или перенос файла).
- Один коммит = одна строка таблицы §0 (один файл). Инфраструктура
  (§2) и серверная часть (§5) — отдельные коммиты.
- Формат сообщений (по конвенции репозитория):
  `i18n(web): вынос строк FilesPage`, `i18n(web): инфраструктура словарей`,
  `i18n(server): AI_LANG + английский промпт агента`.
- Pre-commit hook (`scripts/pre-commit.sh`) гоняет eslint + tsc + vitest +
  build на каждом коммите — это и есть пошаговая проверка, специально
  ничего запускать не нужно. Коммиты только с документацией — с
  `--no-verify` (документированное исключение в AGENTS.md).
- Два словаря ведём строго парами: ни одного коммита, где строка есть в
  `ru.ts`, но нет в `en.ts` (тип `en` от `typeof ru` это гарантирует —
  см. §2).

## 2. Инфраструктура (первый кодовый коммит)

Новые файлы:

- `web/src/i18n/ru.ts` — плоский словарь, ключи `<пространство>.<смысл>`
  в camelCase: `files.title`, `files.deleteConfirm`, `common.loading`.
  Пространства — по страницам/компонентам + `common.*` для повторяющихся
  (кнопки «Сохранить/Отмена/Удалить», «Загрузка…» и т.п.).
  Значение — строка с `{placeholders}` **или** функция
  `(params) => string` (нужно для склонений, см. §3).
- `web/src/i18n/en.ts` — `const en: typeof ru = { ... }`. Типовая
  привязка к `typeof ru` делает пропуск ключа и лишний ключ ошибкой
  компиляции — критично, тестов у фронтенда нет. Для функций-значений
  паритет сигнатур проверяет тест (§6).
- `web/src/i18n/index.ts`:
  ```ts
  export type Lang = 'ru' | 'en';
  export type I18nKey = keyof typeof ru;
  // t(key, params?) — строка: подстановка {name}; функция: вызов с params.
  // useT(): { t, lang, setLang } — React context.
  // locale(): 'ru-RU' | 'en-US' — для toLocale* (см. §4).
  ```
  - `LangProvider` монтируется в `main.tsx` вокруг `<App />` — выше
    auth-guard, иначе `LoginPage` останется без контекста.
  - Инициализация: `localStorage 'sc-lang'` → `navigator.language`
    (`ru*` → `ru`, иначе `en`). Чтение/запись localStorage — в try/catch
    по образцу `sc-theme` (App.tsx:114–171).
  - Переключение — `setLang` + `localStorage`, без перезагрузки. Язык —
    стейт React: keep-alive вкладки и WS-панель агента не перемонтируются
    (тот же инвариант, что у темы; проверяется в §7).
- Переключатель в сайдбаре — рядом с `theme-switch` (App.tsx:566–571),
  по тому же образцу (строка «Язык», две кнопки RU/EN).

Критерий готовности коммита: `tsc`/`lint`/build зелёные, словари
содержат горстку ключей, переключатель меняет их в UI на лету.

## 3. Правила выноса строк

1. **Выносим только user-visible строки**: текст JSX, `placeholder`,
   `title`, `aria-label`, тексты `confirm()`/`alert()`, клиентские тексты
   ошибок и уведомлений. Комментарии, имена CSS-классов, ключи
   localStorage, WS-протокол — не трогаем.
2. **Серверные тексты приходят готовыми — не переводим** (слой 2,
   осознанное ограничение v1): тела ошибок из API, сообщения алертов с
   сервера, вывод команд. Клиентские заглушки вокруг них («Ошибка
   запроса», «Нет соединения») — выносим.
3. **Интерполяция — только именованные плейсхолдеры** `{name}`,
   позиционные запрещены (порядок слов в языках разный).
4. **Склонения и числительные — функции в словаре**, не конкатенация:
   ```ts
   // ru.ts
   'time.hoursAgo': (n: number) => `${n} ${plural(n, 'час', 'часа', 'часов')} назад`,
   // en.ts
   'time.hoursAgo': (n: number) => `${n} hour${n === 1 ? '' : 's'} ago`,
   ```
   Хелпер `plural(n, one, few, many)` кладём в `i18n/ru.ts` (это
   ru-специфика). Кандидаты из инвентаря: `pluralHours`/«мин назад» в
   `api.ts`, строки usage в `AgentPage` («N симв.»), счётчики
   контейнеров/файлов. При сомнении — нейтральная формулировка
   («Файлов: 5») предпочтительнее склонения.
5. **Единицы размеров** (`Б/КБ/МБ` vs `B/KB/MB`) — массив единиц в
   словаре, `formatBytes` берёт из него.
6. **Один ключ — одно место использования**; общие строки («Отмена») —
   в `common.*`, не плодим дубли в пространствах страниц.
7. **Ключи не переводим дословно** — имя ключа описывает смысл
   (`agent.approvalTitle`), а не русский текст.
8. Не меняем поведение: пробелы, переносы, пунктуация в выносимой строке
   — ровно как в оригинале. Вынос — чистый рефакторинг, ни один коммит
   не должен менять UI в ru-режиме (проверка §7).

## 5. Серверная часть (слой 3 — язык агента)

Отдельный коммит после фронтенда:

- `config.ts`: `ai.lang`: `process.env.AI_LANG === 'en' ? 'en' : 'ru'`
  (неизвестные значения → `ru`, не валимся).
- Текст системного промпта (сейчас собирается в `agent.ts:110–172`) и
  `PLAN_MODE_INSTRUCTION` (`plan.ts:7`) выносим в
  `server/src/ai/prompts.ts`: два экспортированных варианта ru/en,
  выбор по `config.ai.lang`. Динамические куски (имена подключённых
  серверов, блок памяти) остаются интерполяцией в `agent.ts` — эти
  строки-склейки («Сейчас к диалогу подключены серверы: …») тоже
  получают en-вариант.
- Правила `[[SUGGEST]]` в обоих вариантах промпта — дословно тот же
  маркер и тот же протокол (фронтенд парсит маркер, а не язык);
  подсказка генерируется моделью на языке промпта.
- `.env.example` и таблица env в `AGENTS.md` — строка `AI_LANG`.
- Диалоги, `MEMORY.md`, имена профилей, сохранённые команды — данные
  пользователя, не переводятся и не мигрируются.

## 6. Тесты

- `server/test/i18n.test.ts` — по прецеденту `alerts-merge.test.ts`
  (клиентский модуль `web/src/*` гоняется серверным раннером vitest):
  1. **паритет ключей** ru/en: множества ключей равны (страховка поверх
     `typeof ru` — ловит и функции-значения);
  2. **паритет плейсхолдеров**: для каждого строкового значения множество
     `{name}` в ru равно множеству в en;
  3. `t()` подставляет параметры и выбирает словарь по языку;
  4. дефолт языка: `navigator.language` `ru-RU` → ru, `en-US` → en,
     пусто → en; сохранённый `sc-lang` приоритетнее navigator.
- `server/test/` — unit на выбор промпта: при `AI_LANG=en` системный
  промпт и `PLAN_MODE_INSTRUCTION` английские, маркер `[[SUGGEST]]`
  присутствует в обоих.
- Статические проверки (гоняет pre-commit hook): `eslint src` в web,
  `tsc --noEmit` в server, `vitest run` в server, `npm run build` в web
  (включает свой tsc).

## 7. Приёмка (финальный чек-лист)

Автоматическое:

```bash
# 1. Кириллицы в UI-строках не осталось: все попадания — комментарии
#    или словарь ru.ts (вызовы plural() внутри ru.ts — ок)
grep -rnP '\p{Cyrillic}' web/src --include='*.ts' --include='*.tsx' | grep -v 'i18n/'
# каждое попадание глазами классифицировать: комментарий — ок, строка — баг

# 2. Литералы локали вынесены
grep -rn 'ru-RU' web/src   # только web/src/i18n/index.ts

# 3. Полный прогон
cd server && npm run build && npm test
cd web && npm run build && npm run lint
npm audit  # без уязвимостей (зависимостей не добавляем — аудит формальный)
```

Ручное (dev-режим, `scripts/docker-dev.sh up`):

- [ ] Оба языка, проход по всем вкладкам: Обзор, Терминал, Файлы,
      Docker, Базы данных, Службы, Nginx, Порты, Cron, Расходы AI,
      Серверы (сниппеты), логин, модалки (профиль, disk-usage, алерты,
      подтверждения агента). Ни одной русской строки при en
      (серверные тексты ошибок — известное исключение).
- [ ] Переключение языка без перезагрузки: текст меняется на лету;
      открытый терминал жив (WS не рвётся), скрытые keep-alive вкладки
      не перемонтируются (состояние страниц сохраняется).
- [ ] `sc-lang` в localStorage; F5 сохраняет выбор; чистый браузер с
      `ru`-локалью стартует на ru, с другой — на en.
- [ ] Даты/числа: в en-режиме форматирование по `en-US` (страницы
      «Расходы AI», «Nginx» — сроки сертификатов, спарклайны).
- [ ] Плейсхолдер-подсказка `[[SUGGEST]]` в поле ввода агента: Tab
      подставляет текст, автоотправки нет (инвариант из AGENTS.md).
- [ ] Агент при `AI_LANG=en`: отвечает по-английски, цикл с инструментами
      и approve/reject-бар работают как раньше (ручной сценарий
      `server/test/agent.manual.mjs` с моком — опционально).
- [ ] Ru-режим после всех изменений пиксельно тот же, что на `main`
      (вынос — чистый рефакторинг; подозрительные места — диффом скриншотов
      или глазами по основным страницам).

## 8. Риски и как их гасим

- **Пропущенная строка** — финальный grep (§7.1) + ручной проход.
  «Тысяча порезов» ловится только так, типы здесь не помогают.
- **Сломанная интерполяция** в en — тест паритета плейсхолдеров (§6).
- **`t()` вне провайдера** (LoginPage, ранние return'ы в App) —
  провайдер в `main.tsx`, проверка логина ручным проходом;
  `react-hooks/rules-of-hooks` в eslint страхует от вызова `useT()`
  после условного return (реальный прецедент — эпик 20).
- **Рассинхрон словарей в будущих фичах** — `typeof ru` на `en.ts`
  делает это ошибкой компиляции; тест паритета — второй эшелон.
- **Строки с разметкой** (JSX внутри предложения: «нажмите <b>Enter</b>») —
  не пытаемся выносить в одну строку с тегами: разбиваем на части
  (`common.press` + `common.enter`) или перефразируем, чтобы JSX стоял
  по краям. Никакого `dangerouslySetInnerHTML` ради перевода.
- **Длина en-строк** — английский обычно короче русского, но кнопки и
  таббар проверить глазами (фиксированные ширины в сайдбаре/таббаре).
