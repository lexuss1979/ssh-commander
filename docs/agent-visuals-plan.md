# План: визуализации в сообщениях AI-агента (mermaid + ```chart)

Цель: агент может вставлять в ответы диаграммы и графики, чтобы делать сообщения нагляднее (сравнения, доли, динамика, схемы процессов).

## Решение (кратко)

Два канала, оба — fenced code-блоки в тексте ответа:

1. **` ```mermaid `** — уже был реализован (`web/src/components/Mermaid.tsx`): flowchart, sequenceDiagram, stateDiagram, erDiagram, gantt, pie, xychart-beta. В рамках этого эпика модель просто *узнаёт* о возможности — через системный промпт.
2. **` ```chart `** — новый блок с JSON-спекой числовых данных, рендерится собственным SVG-компонентом без зависимостей.

## Почему так

- **Персист бесплатно**: контент диалогов хранится как plain markdown (`server/src/ai/dialogues.ts`) — code-блок переживает перезагрузку диалога и перерисовывается. Альтернатива «инструмент агента + кастомная карточка по `tool_result`» отвергнута: выводы инструментов восстанавливаются из истории только как текст, график пропадал бы.
- **Без chart-библиотек**: осознанное решение проекта (`docs/metrics-history-plan.md` — «тянуть recharts/uPlot ради двух спарклайнов не хочется»). Свой SVG — прецедент `web/src/components/Sparkline.tsx`.
- **Не трогаем безопасность агента**: график — часть текста ответа, никаких новых инструментов, guard, approval и redactSecrets не меняются.

## Формат ` ```chart `

```json
{
  "type": "bar" | "line" | "pie",
  "title": "необязательно",
  "unit": "необязательно (GB, %, шт...)",
  "labels": ["подпись категории", "..."],
  "series": [{ "name": "...", "data": [1, 2, 3] }]
}
```

- `bar` — сгруппированные столбцы (группа = label, столбец = series); домен Y всегда включает ноль, отрицательные значения поддержаны (линия нуля).
- `line` — ломаная на series, X — категории labels равномерно (не временная ось).
- `pie` — ровно одна series неотрицательных значений с положительной суммой; labels — доли; легенда со значениями и процентами.
- Лимиты (отсекают мусор и раздувание контекста): labels ≤ 24, series ≤ 6, подписи ≤ 60 символов, длина каждого `data` == длине `labels`, все значения — конечные числа (`NaN`/`Infinity` отклоняются).

## Реализация

- `web/src/chart-spec.ts` — чистый модуль (без React/i18n, прецедент `alerts.ts`): `parseChartSpec(text): ChartSpec | null` (JSON.parse + структурная валидация + лимиты) и `formatChartValue` (компактные k/M). Тестируется серверным раннером — `server/test/chart-spec.test.ts` (прецедент `alerts-merge.test.ts`).
- `web/src/components/Chart.tsx` — SVG-рендерер: заголовок/легенда — HTML (свободный перенос), только плот — SVG (`viewBox 560×300`); цвета — CSS-переменные `--chart-1..6` (обе темы), сетка/подписи — `var(--border-soft)`/`var(--muted)`; на переполненных осях подписи X прореживаются (≤ 12).
- `web/src/components/Markdown.tsx` — ветка `lang === 'chart'` в `CodeBlock`: валидная спека → `<Chart>`, иначе — обычный `<pre>`.
- `server/src/ai/prompts.ts` — `visualsNote(lang)` (ru/en): рассказывает модели о ```mermaid и ```chart со схемой и примером; правила: только реальные собранные данные, ≤ 24 меток, подписи на языке диалога, валидный JSON, не в каждый ответ. Подключена безусловно в `agent.ts` рядом с `webSearchNote`. Существующие ru-литералы промпта не тронуты.
- i18n: один ключ `markdown.chartAria` (aria-label блока) в обоих словарях.

## Поведение при стриминге

Markdown рендерится на каждую дельту. Незавершённый JSON в ```chart mid-stream невалиден → показывается обычным code-блоком и «оживает» при завершении. Ошибка **не защёлкивается** (в отличие от mermaid-фолбэка с `markdown.mermaidError` — там parse error почти всегда финален): parse делается `useMemo` от текущего текста блока, состояние не хранится.

## Безопасность

Спека парсится только как JSON + валидация структуры; подписи выводятся React'ом в `<text>`/DOM (авто-экранирование); никакого eval и raw HTML. Mermaid — как прежде, `securityLevel: 'strict'`.

## Осознанно не делаем (v2, если понадобится)

- Экспорт графика в PNG/CSV, интерактивность (tooltip/zoom).
- Временная ось X в ```chart (для неё есть LoadChart на вкладке «Обзор»).
- Stacked bar, scatter, multi-pie — спека расширяема, но YAGNI.
