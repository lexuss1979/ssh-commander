# Обнаруживаемость скрытых функций (discoverability)

Дата: 2026-10-06. Статус: реализовано (уровень 1 + ядро и три подсказки уровня 2; пункт 4 порядка — строка в AGENTS.md).

Проблема: в продукте есть функции, о которых пользователь не может узнать из интерфейса — они спрятаны в модалках, за неприметными кнопками или объяснены только в `title=`-тултипе. Список от автора продукта:

1. Подключение нового VPS через root + пароль (bootstrap).
2. Подключение нескольких серверов к диалогу агента.
3. Автопредложение следующего действия агента (подстановка по Tab).
4. Plan-mode агента.
5. Импорт/экспорт серверов между компьютерами.
6. Проброс портов (SSH-туннели).
7. Скачивание целых папок в файловом менеджере.
8. Закрепление логов в файловом менеджере.

## Принципы

- **Два уровня.** Уровень 1 — точечные доработки в местах, где функция физически спрятана (пустые состояния, хинты в формах). Уровень 2 — минимальное ядро одноразовых контекстных подсказок («did you know») для функций, которые зависят от контекста и не имеют постоянного места на экране.
- **Без тура.** Интерактивный тур при первом запуске не делаем: дорого, большинство проматывает.
- **Подсказка показывается один раз.** Флаг в `localStorage`, закрытие по ✕ навсегда. Подсказка никогда не блокирует работу и не повторяется.
- **Подсказка гаснет сама**, когда функцией воспользовались (подключили второй сервер, закрепили лог, скачали папку) — независимо от ✕.
- **Два языка сразу.** Каждая новая строка добавляется в `web/src/i18n/ru.ts` и `web/src/i18n/en.ts` одновременно; паритет проверяют типы (`en` = `typeof ru`) и `server/test/i18n.test.ts`. Комментарии в коде — на английском.
- Существующие конвенции: хинт-строки с префиксом `*.hint`/`*Hint*`, пустые состояния — класс `.empty-state` (образец — панель агента, `AgentPage.tsx:971`), настройки клиента — `localStorage` с префиксом `sc-` (как `sc-lang`, `sc-alerts`).

## Ядро уровня 2: модуль одноразовых подсказок

Новый модуль `web/src/tips.ts` и компонент `web/src/components/TipBanner.tsx`.

`tips.ts`:

```ts
export type TipId =
  | 'agent-multi-server'
  | 'files-folder-download'
  | 'files-log-pin';

export function isTipSeen(id: TipId): boolean;
export function markTipSeen(id: TipId): void;
```

- Хранилище: `localStorage`, ключ `sc-tips`, значение — JSON-объект `{[tipId]: true}`. Чтение/запись в try/catch (localStorage может быть недоступен — тогда подсказка просто показывается, это безопасный дефолт).
- Чистый модуль без React — по образцу `web/src/alerts.ts`; при желании покрывается тестами раннером сервера (как `test/alerts-merge.test.ts`), но в v1 тесты не обязательны.

`TipBanner.tsx`:

- Props: `{ id: TipId; children: ReactNode }`. Если `isTipSeen(id)` — рендерит `null`.
- Разметка: `<div className="tip-banner">` + текст (`children`) + кнопка ✕ (`aria-label` из нового ключа `tips.dismiss`), которая вызывает `markTipSeen(id)` и скрывает баннер (локальный state).
- Стили: новый класс `.tip-banner` в `web/src/styles.css` — приглушённая плашка (фон/бордер на CSS-переменных, работает в обеих темах), не toast: не исчезает сама и не перекрывает контент.

Новые i18n-ключи ядра: `tips.dismiss` (ru: «Понятно, больше не показывать» / en: «Got it, don't show again»).

### Проверка глазами (ядро)

1. `scripts/docker-dev.sh up`, открыть `http://localhost:5173`.
2. Любая подсказка (см. пункты ниже) появляется как плашка с текстом и ✕.
3. Нажать ✕ → плашка исчезла; перезагрузить страницу (F5) → плашка НЕ появилась снова.
4. В DevTools Console выполнить `localStorage.removeItem('sc-tips')`, перезагрузить → плашка появилась снова.
5. Переключить язык в «Настройки» → «Интерфейс» (ru ↔ en): текст плашки и подпись ✕ меняются, факт «уже видел» сохраняется (флаги не зависят от языка).
6. Повторить в светлой и тёмной теме: плашка читаема в обеих.
