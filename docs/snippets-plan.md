# План: эпик 18 — сохранённые команды и запуск на нескольких серверах

> Эпик 18 из `docs/roadmap.md` (Tier 2): «у агента мульти-серверный режим
> есть, у человека — нет» — список сниппетов плюс выполнение на выбранных
> профилях с выводом таблицей («проверить версию / перезапустить / посмотреть
> место на трёх машинах»).
> Статус: план, ожидает согласования. Дата плана: 2026-08-23.
> Сервер + фронтенд. Новых зависимостей нет.

## Контекст: что уже есть

- Эталонный стор-паттерн — `services/db-connections.ts` (и `profiles.ts`,
  `ai/dialogues.ts`): zod-валидация, атомарная запись tmp+rename, битый JSON
  → `*.corrupt-<timestamp>` + отказ persist до рестарта. Новый стор
  `snippets.ts` копирует его целиком.
- `exec` (`ssh/manager.ts`): таймаут по умолчанию 60 c, лимит вывода 2 МБ
  раздельно на stdout/stderr, `ExecResult {code, stdout, stderr}` **без
  флага обрезки** (молчаливый кап) — серверная обрезка до лимита ответа
  обязательна.
- Параллельный прогон по профилям — `Promise.allSettled` + `withTimeout`
  на профиль в `services/overview.ts` (упавший сервер не роняет сводку) —
  тот же паттерн для запуска сниппетов.
- Мульти-серверный режим агента готов: `attach_server`/`connect_server`,
  `extraProfileIds` в диалогах, `list_servers`, инструменты с параметром
  `server`. Эпик закрывает разрыв «у человека нет» — но сам агент не трогает.
- ServersPage (`web/src/pages/ServersPage.tsx`) — сводная страница всех
  профилей: polling `/api/overview` раз в 5 c (только при `visible`),
  карточки с метриками, пропы `{showError, visible, onOpenProfile}`.
  Естественное место раздела «Команды» (roadmap); пропа `onAskAgent`
  у страницы нет — добавить по паттерну остальных страниц.
- «В чат» — `agentRequest`/`handleAskAgent` (`App.tsx:230`), режим `'send'`
  для уже собранного отправителем текста (LogViewer, SQL-консоль);
  `'explain'` жёстко говорит «вывод терминала» — для результата сниппета
  это враньё в промпте.
- Команда выполняется **как есть**: это ручной инструмент уровня терминала,
  не агент — deny-лист `guard.ts` здесь не применяется (сделал бы сниппет
  бесполезным, roadmap). Защита — подтверждение в UI со списком целей.

## Решение

### 1. Стор `server/src/services/snippets.ts` + `data/snippets.json`

- Входная схема `snippetInputSchema`:
  `{name: string 1..100, command: string 1..10000, description?: string ≤500,
  profileIds?: string[] | null}` (`profileIds` — до 50 строк; `null` =
  «доступен на всех серверах», решение roadmap; отсутствие поля = null).
- Хранимая запись — входная + `{id: crypto.randomUUID().slice(0, 8),
  createdAt, updatedAt}` (как db-connections). `storeSchema =
  {snippets: array}`.
- load/persist ровно по `db-connections.ts`: ENOENT → `[]`; битый JSON →
  `*.corrupt-<ts>` + `corrupt = true` + отказ persist с понятным текстом до
  рестарта; запись tmp+rename; кэш в памяти.
- Функции: `listSnippets()`, `getSnippet(id)`, `requireSnippet(id)`,
  `createSnippet(input)`, `updateSnippet(id, input)` (полная замена полей по
  схеме — частичный update не нужен: секретов нет), `deleteSnippet(id)`.
- Секретов в сниппетах нет — «safe»-маппинг не нужен, наружу отдаём запись
  как есть. Заметка: команда может содержать пароли — осознанный риск
  уровня терминала (подпись в UI, зафиксировать в AGENTS.md при сдаче).

### 2. Маршруты `server/src/routes/snippets.ts`

Монтирование: `app.use('/api/snippets', requireAuth, snippetsRouter)` в
`src/index.ts`. CRUD с zod `safeParse` → 400:

- `GET /api/snippets` — все сниппеты.
- `POST /api/snippets` — создать, 201.
- `PUT /api/snippets/:id` — обновить (400/404).
- `DELETE /api/snippets/:id` — удалить, 204.

**`POST /api/snippets/run`** — тело
`{snippetId?: string, command?: string, profileIds: string[]}`:

- **XOR**: ровно одно из `snippetId`/`command` (400 «Укажите сниппет или
  команду» / «Укажите только одно из snippetId или command»).
- `snippetId` → команда из стора (`requireSnippet` → 400, если не найден).
- `profileIds`: массив 1..10 (400 за пределами; пустой — 400), дедуп,
  каждый существует — `requireProfile`, при отсутствующих — 400 со списком.
- Параллельный прогон: `Promise.allSettled(profileIds.map(p => withTimeout(
  exec(p, command, {timeoutMs: RUN_TIMEOUT_MS}), …)))`. `RUN_TIMEOUT_MS =
  120000` (перезапуск службы дольше дефолтных 60 c). `withTimeout` — тот же
  локальный хелпер, что в `overview.ts` (guard-таймаут на профиль: мёртвый
  сервер не вешает весь ответ).
- **Команда передаётся в `exec` как есть** — shell-строка уровня терминала;
  `shq` НЕ применяется (это не аргумент, а команда). Никакого deny-листа.
- Маппинг `mapRunResults` (чистая функция под unit-тесты):
  `PromiseSettledResult[]` → `{profileId, ok, code, stdout, stderr, ms,
  truncated}[]`; `ok` — `code === 0`; транспортный отказ/таймаут (rejected)
  → `ok: false`, `error: <текст>`, `code: null`; `ms` — замер вокруг exec.
  **Обрезка вывода: `RUN_RESULT_TEXT_LIMIT = 100_000` символов на поток** +
  `truncated: true` (10 профилей × 2 МБ × 2 потока = 40 МБ в одном JSON —
  нельзя; честная пометка обрезки вместо молчаливой, обрезает и тот случай,
  когда внутренний кап exec в 2 МБ уже сработал).
- Ответ: `{command, results}` — `command` эхом (что реально выполнялось)
  для UI и «В чат».
- Отказ одного сервера не роняет ответ — `Promise.allSettled` (roadmap).

### 3. Фронтенд: раздел «Команды» на ServersPage

- `App.tsx`: передать в ServersPage проп `onAskAgent={handleAskAgent}`
  (паттерн TerminalPage/FilesPage).
- Новый компонент `web/src/components/SnippetsSection.tsx`, пропсы
  `{showError, onAskAgent, servers: OverviewServerEntry[] | null}` — цели
  берутся из опрошенного `/api/overview` (`data.servers`: id + name +
  username@host); недоступные серверы тоже можно выбрать — `exec` честно
  вернёт ошибку в результатах.
- Секция под сеткой карточек: список сниппетов (имя + превью команды
  mono-строкой), кнопки «Новый» / «✎» / «🗑» (confirm) / «Выполнить».
- Форма редактирования (модалка `Modal`): `name`, `command` (textarea mono),
  `description`, чекбокс «на всех серверах» (= null) / список профилей
  чекбоксами (заполняется из `servers`).
- Запуск: выбор цели — чекбоксы серверов; разовая команда без сохранения —
  поле «или команда» (textarea) вместо выбора сниппета (XOR как на сервере).
  **Подтверждение-модалка до выполнения**: команда mono-блоком + явный
  список целей (`name — username@host`) + предупреждение «Команда
  выполняется без фильтрации и может изменить состояние серверов; запуск
  на N серверах сразу» + «Выполнить»/«Отмена» (roadmap: запуск на трёх
  машинах стоит показать до, а не после).
- Результаты: аккордеон по серверам — имя, бейдж кода возврата
  (0 — зелёный, ≠0 — красный, транспортный отказ — «ошибка»), `ms`,
  stdout/stderr mono-блоками (`.code-block`, при `truncated` — пометка
  «вывод обрезан»), кнопка «В чат» на каждом сервере:
  `onAskAgent(text, 'send')` — «Объясни вывод команды "<command>" на сервере
  <name> (exit code N): ```хвост вывода ≤4 КБ```». Режим `'send'`, как в
  LogViewer — панель агента текущего активного профиля; при необходимости
  агент подключит остальные серверы через `connect_server` (механика есть).
- Во время запуска — per-server статус «выполняется…», действия раздела не
  блокируются целиком. Polling разделу не нужен (только ручные действия) —
  `visible`-паузы не требуется, всё и так молчит на скрытой вкладке.

### 4. CSS (`web/src/styles.css`)

`.snippets-*` (строка сниппета, превью mono, аккордеон результатов, бейджи
кода) и `.code-block` (pre со скроллом, `scrollbar-gutter: stable`) на
CSS-переменных.

## Отклонённые альтернативы

- **Отдельная вкладка «Команды»** — roadmap: раздел на «Серверах»: сводка
  по всем профилям и цели запуска уже рядом. Если раздел разрастётся —
  вынести позже отдельным шагом.
- **Сниппеты per-profile** — roadmap: глобальный стор `data/snippets.json`;
  сниппет — «команда на всех/выбранных», привязка к профилю была бы лишней
  сущностью (те же команды «проверить версию» нужны на всех машинах).
- **Фильтрация команды deny-листом** — сделала бы инструмент бесполезным
  (roadmap); защита — подтверждение со списком целей, как у терминала.
- **SSE/стрим результатов** — запуск короткий (≤120 c на профиль), вывод
  разовый; аккордеон после завершения проще и достаточно. Follow-слоты
  `stream-limits.ts` не расходуем.
- **«В чат» сразу в мульти-серверный диалог (attach всех целей)** — v1 шлёт
  в текущий диалог активного профиля с текстом вывода; авто-attach всех
  серверов запуска — шум в списке серверов диалога; агент подключит нужный
  по запросу.
- **stdin/пароль в сниппетах (sudo-механика)** — v1 без sudo: команда с
  интерактивом завершится ошибкой, как в терминале без пароля. Sudo —
  отдельный шаг, если понадобится.

## Риски

- **Массовый запуск деструктивной команды** — подтверждение с явным
  списком целей рендерится до кнопки «Выполнить»; список целей — часть
  модалки, а не мелкий текст.
- **Большие выводы** — внутренний кап exec 2 МБ + серверная обрезка
  100 КБ на поток с `truncated`; UI — `.code-block` со скроллом.
- **Секреты в командах сниппетов** — осознанный риск уровня терминала
  (roadmap: «как и в самом терминале»); подпись в форме ввода и в
  AGENTS.md при сдаче.
- **Профиль удалён между выбором целей и запуском** — сервер валидирует
  все цели до первого exec (400 со списком), ничего не запустится «наполовину».
- **Интерактивные команды (sudo, запрос ввода)** — без stdin выполнение
  завершится ошибкой/зависанием до таймаута 120 c; в v1 без sudo — честная
  ошибка, как в терминале без пароля.
