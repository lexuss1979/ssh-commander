# План: выделение в терминале → «открыть в новом чате» / «добавить в чат»

> Пункт бэклога (`docs/roadmap.md`, секция Backlog). Статус: спланирован,
> ожидает реализации. Дата плана: 2026-08-20. Только фронтенд (`web/`):
> сервер и WS-протокол не меняются — создание диалога
> (`POST /api/ai/dialogues`) и отправка сообщения (`message`) уже есть.

## Контекст: как работает «Спросить агента» сейчас

- `web/src/pages/TerminalPage.tsx` — `collectTerminalContext(term)`:
  выделение (`getSelection()`, обрезка до 4 КБ) или фолбэк «последние ~30
  непустых строк буфера»; кнопка «Спросить агента» вызывает
  `onAskAgent(text)` (проп из App).
- `web/src/App.tsx` — `handleAskAgent`: раскрывает панель агента и кладёт
  `agentRequest = { id: Date.now(), text, profileId }`; запрос уходит панели
  того профиля, чей терминал его прислал (keep-alive панели, фильтр по
  `profileId` при передаче пропа), сбрасывается `onAgentRequestConsumed`.
- `web/src/pages/AgentPage.tsx` (effect с `lastHandledRequestRef`) — дедуп
  по `id`, шаблон «Объясни этот вывод терминала (сервер X): ```…```»;
  при готовом WS и свободном агенте — авто-отправка, иначе prefill поля
  ввода тем же текстом.

## Что добавляем

Два новых действия, работающие **только на выделении** (без выделения —
недоступны; фолбэк «хвост буфера» остаётся эксклюзивом «Спросить агента»):

- **«Открыть в новом чате»** — создать диалог (`POST /api/ai/dialogues`)
  и автоматически отправить выделение первым сообщением;
- **«Добавить в чат»** — вставить выделение в поле ввода текущего диалога
  (prefill без отправки), чтобы дополнить своим вопросом.

## Решение

### 1. UI в TerminalPage: меню у кнопки «Спросить агента»

«Спросить агента» остаётся отдельной кнопкой без изменений — частый
сценарий не должен получать лишний клик. Рядом добавляется компактная
кнопка «В чат ▾», открывающая меню из двух пунктов (по образцу dropdown'а
«+» серверов в AgentPage: обёртка `position: relative`, абсолютное меню,
закрытие по клику вне и Escape — маленький effect, паттерн `historyOpen`).

Трекинг выделения: в effect'е создания терминала подписка
`term.onSelectionChange(() => setHasSelection(term.hasSelection()))` →
стейт `hasSelection`; пункты меню live активны только при выделении,
иначе disabled с подсказкой «Сначала выделите текст в терминале».

Клик по пункту: `term.getSelection().trim().slice(-ASK_AGENT_MAX_CHARS)`
— та же обрезка до 4 КБ с сохранением хвоста, что и в
`collectTerminalContext` (выделение может быть на мегабайты);
страховка от пустоты — `showError` и выход, затем `term.clearSelection()`
и `onAskAgent(text, mode)`.

### 2. Проброс режима: `agentRequest.mode`

- Тип `AgentAskMode = 'explain' | 'new-dialogue' | 'prefill'` — в
  `web/src/types.ts` (общий для TerminalPage/App/AgentPage).
- Проп TerminalPage: `onAskAgent?: (text: string, mode?: AgentAskMode)`;
  значение по умолчанию `'explain'` — существующие вызовы не меняются.
- App: поле `mode` в стейте `agentRequest`, `handleAskAgent` его
  пробрасывает. Раскрытие панели и маршрутизация по `profileId` — без
  изменений.
- Тип пропа AgentPage тоже расширяется: `agentRequest?:
  { id: number; text: string; mode?: AgentAskMode } | null`
  (сейчас `{ id; text }`).

### 3. AgentPage: три ветки обработки

Шаблон сообщения вынести в хелпер `terminalContextMessage(text,
serverName)` — «Объясни этот вывод терминала (сервер X):\n```\n…\n```»;
используется ветками `explain` и `new-dialogue`.

- **`explain`** — ровно как сейчас: авто-отправка в текущий диалог при
  свободном агенте, иначе prefill. Не трогаем.
- **`prefill`** — всегда только поле ввода, авто-отправки нет ни при каком
  состоянии агента. Вставка не затирает набранное:
  `setInput(prev => prev ? prev + '\n\n' + block : block)`, где `block` —
  цитата **без** инструкции («Вывод терминала (сервер X):\n```\n…\n```»
  + пустая строка под вопрос пользователя). Добавить `inputRef` к textarea
  `.agent-input`: после вставки — фокус и курсор в конец.
- **`new-dialogue`**:
  - агент `running` → ничего не делать + `showError` «Агент выполняет
    задачу — дождитесь завершения» (паттерн `removeDialogue`/`startAudit`;
    молча отменять бегущий цикл созданием нового диалога — плохо).
    Проверка — через `runningRef.current`: весь effect `agentRequest`
    читает состояния только через refs (`connectedRef`, `runningRef`,
    `activeDialogueIdRef`), чтобы смена состояния не расходовала запрос
    повторно;
  - иначе `startNewDialogue()` (модифицировать: вернуть `dialogue.id`),
    после успешного POST — `pendingSendRef.current = { content,
    dialogueId }` (ref заполняется только после успеха, при ошибке
    `startNewDialogue` сам покажет toast);
  - в WS-effect'е, в `ws.onopen` после `setConnected(true)`: если
    `pendingSendRef.current` заполнен и `dialogueId === activeDialogueId`
    (замыкание effect'а видит актуальный `activeDialogueId` — он в deps;
    гонка «пользователь переключил диалог, пока коннектился» закрыта
    проверкой id) — добавить user-сообщение в ленту, отправить WS
    `message`, очистить ref. План-режим не применяется (`planMode: false`):
    это обычный вопрос по выводу, а не планирование задачи;
  - **очистка протухшего pending** — в cleanup WS-effect'а, но
    **условная**: сбрасывать ref только когда
    `pendingSendRef.current?.dialogueId === activeDialogueId` (id из
    замыкания именно этого effect'а). Безусловная очистка роняла бы
    основной путь — ref заполняется ещё до ре-рендера от
    `setActiveDialogueId`, и cleanup старого effect'а выполняется уже
    после заполнения. Условная же убирает ровно протухший случай:
    пользователь переключился на другой диалог до `onopen` — cleanup
    effect'а «своего» диалога сбрасывает pending, и сообщение не уйдёт
    при следующем открытии этого диалога через час.

Смена `activeDialogueId` роняет старый WS — но ветка уже проверила, что
агент свободен; по поведению это то же, что кнопка «Новый диалог» в
тулбаре. Заголовок нового диалога сервер сформирует из первого сообщения
— бэкенд не трогаем.

### 4. CSS (`web/src/styles.css`)

Классы `.terminal-ask-menu`-обёртка и пункты по образцу
`.server-add-dropdown`/`.server-add-item` (hover, `disabled`-состояние,
темы через CSS-переменные, `z-index` над терминалом).

## Отклонённые альтернативы

- **Все три действия в одном меню** — лишний клик на частом сценарии
  «Спросить агента»; кнопка остаётся standalone.
- **Popover прямо на выделении в xterm** (по mouseup над выделением) —
  xterm не даёт встроенного меню выделения: ручное позиционирование
  хрупко при скролле/респрайте/переключении вкладок; кнопка в тулбаре
  предсказуемее и соответствует сложившемуся паттерну.
- **Первое сообщение нового чата — голый блок вывода без вопроса** —
  модель отвечает расплывчато; оставляем шаблон «Объясни этот вывод…»
  (отличие фичи — в свежем диалоге, а не в тексте).

## Затрагиваемые файлы

- `web/src/types.ts` — тип `AgentAskMode`;
- `web/src/pages/TerminalPage.tsx` — `hasSelection`, меню «В чат ▾»,
  обрезка 4 КБ, `onAskAgent(text, mode)`;
- `web/src/App.tsx` — тип `agentRequest` (+`mode`), `handleAskAgent`;
- `web/src/pages/AgentPage.tsx` — тип пропа `agentRequest` (+`mode`),
  ветки mode, `terminalContextMessage`, `pendingSendRef` + отправка в
  `ws.onopen` + условная очистка в cleanup, `inputRef`/фокус,
  `startNewDialogue` возвращает id;
- `web/src/styles.css` — меню;
- `docs/roadmap.md`, `AGENTS.md`.

Без изменений: сервер, WS-протокол, REST API.

## Проверки

- `cd web && npm run build` (tsc строгий);
- `cd server && npm run build && npm test` — сервер не меняется, прогон
  по правилам «перед сдачей» (известно: 2 теста `keys.test.ts` падают на
  Windows из-за chmod — регрессией не считать);
- ручной сценарий:
  - выделение есть → пункты активны; снято → disabled с подсказкой;
  - «Добавить в чат»: панель раскрывается, цитата в поле ввода, ранее
    набранный текст не затёрт, фокус в конце; Enter отправляет как
    обычное сообщение;
  - «Открыть в новом чате»: диалог создаётся, первое сообщение уходит
    автоматически, агент отвечает; прежний диалог цел в истории;
  - во время выполнения агента: «Открыть в новом чате» → toast, ничего
    не рвётся; «Добавить в чат» работает всегда;
  - мульти-профиль: запрос уходит в панель своего профиля (keep-alive),
    в т.ч. когда активен другой профиль;
  - «Спросить агента» не изменился (фолбэк хвоста буфера, prefill при
    занятом агенте);
  - контейнерная сессия терминала — меню доступно и там.
