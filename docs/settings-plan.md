## Зачем

Onboarding задаёт пароль и ключ один раз; но ключ можно пропустить, а
пароль/провайдер со временем меняются. Без UI это означает правку файла
или env + рестарт контейнера — неудобно и неочевидно. «Настройки» закрывают
это: смена пароля (с проверкой текущего), добавление/замена/очистка ключа
AI, смена Base URL. Данные — тот же `data/settings.json`, что у onboarding.

## Бэкенд

### `services/settings.ts` (расширение)

- `updateSettings(patch: { passwordHash?, aiApiKey?, aiApiBase? })` — атомарный
  мерж поверх текущих настроек (tmp+rename, corrupt-guard как раньше).
- `clearAiKey()` / сброс полей: `aiApiKey: undefined` и `aiApiBase: undefined`
  означают «вернуться к env-фолбэку» (settings поверх env — тот же приоритет,
  что в onboarding-плане).

### Эндпоинты (`routes/settings.ts`, монтирование **с** `requireAuth`)

- `GET /api/settings` → `{ passwordVia: 'settings' | 'env', aiApiKeySet: boolean,
  aiApiBase?: string }`. Ключ **никогда не возвращается** — только факт
  «задан/не задан»; `aiApiBase` возвращается, это не секрет.
- `PUT /api/settings` — тело `{ currentPassword?, newPassword?, aiApiKey?,
  aiApiBase? }` (все поля опциональны, валидируются zod):
  - **смена пароля** требует `currentPassword` — проверка через
    `verifyPassword` (settings-хеш или env); неверный → 400 «Неверный текущий
    пароль»; `newPassword` ≥ 8 символов;
  - `aiApiKey` — строка без пробелов/переводов строк; явный `null` — очистить
    (вернуться к env);
  - `aiApiBase` — URL http/https (как в config.ts) или `null` — сброс к env;
  - успех → обновлённый `GET`-ответ (маскированный).
  - Пустой `{}` (ничего не меняем) — 400, чтобы не плодить пустые записи.
- **Сессии при смене пароля**: не инвалидируются (single-user локальный
  инструмент, сессии in-memory; текущая сессия остаётся живой — как в
  терминале при смене профиля). Новые входы — по новому паролю.

### AI-клиент

Без изменений: `getAiConfig()` уже читает settings поверх env; после
`PUT /api/settings` следующие вызовы агента подхватывают новый ключ без
рестарта (чтение с диска на каждый вызов).

## Фронтенд

- `web/src/pages/SettingsPage.tsx` — глобальная страница в сайдбаре
  (секция сайтов, рядом с «Расходы AI»), рендерится как AiCostsPage
  (вне таббара профиля):
  - **Пароль**: текущий + новый + подтверждение, кнопка «Сменить»;
    подпись «Пароль задан: в интерфейсе / в .env» (из `passwordVia`);
  - **AI**: поле ключа (placeholder: «Ключ задан» / «Ключ не задан — агент
    недоступен»; ввод нового ключа заменяет старый; кнопка «Очистить»),
    селект провайдера (DeepSeek / OpenAI / свой URL) → поле Base URL;
  - все действия через try/catch → toast (общий паттерн); после смены
    пароля — toast «Пароль изменён» (сессия жива);
  - загрузка данных при монтировании (`GET /api/settings`), keep-alive не
    требуется (страница глобальная, без WS).
- i18n: все строки — в оба словаря (`settings.*`), паритет типами + тестом.
- App.tsx: добавить вкладку/пункт сайдбара «Настройки» (labelKey `app.settings`)
  рядом с «Серверы»/«Расходы AI».

## Тесты

- `server/test/settings-route.test.ts` — GET маскированный (ключ не утекает,
  `passwordVia` обе ветки); PUT: смена пароля с верным/неверным текущим,
  длина нового, замена/очистка ключа (`null` → env-фолбэк), сброс Base URL,
  пустое тело → 400, `{}` → 400; `requireAuth` на обоих роутах.
- `server/test/settings.test.ts` (расширение) — `updateSettings` мерж, очистка
  полей.
- i18n-паритет новых `settings.*` — автоматически.
- Фронт: lint + ручной проход (смена пароля → старый не пускает, новый
  пускает; замена ключа → агент начинает ходить новым ключом без рестарта).

## Совместимость и краевые случаи

- Настроек нет (env-only) → GET: `passwordVia: 'env'`, `aiApiKeySet` по env;
  смена пароля всё равно доступна (пишет settings, дальше settings поверх env).
- Ключ задан в onboarding и в env — settings в приоритете (как везде).
- Очистка ключа при пустом env-фолбэке → агент недоступен (честный статус
  в UI).
- Session invalidation сознательно не делаем (см. выше).

## Риски

- **Смена пароля с неверным текущим** — 400, счётчик попыток? Не rate-limit'им
  (страница за авторизацией; перебор текущего пароля — атака на самого себя).
- **Ключ в GET не утекает** — проверяется тестом (маскировка, а не фильтр UI).
- **Путаница приоритетов settings/env** — зафиксирована в AGENTS.md и
  проверяется тестом `getAiConfig`.
