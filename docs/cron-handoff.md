## 2. Текущее поведение (проверено по коду)

**Какие источники показывает вкладка «Cron»** (`CronSnapshot` в
`server/src/services/cron.ts`, структура — строки 28–39):

| Источник | Команда | Что это |
|---|---|---|
| `userCrontab` | `crontab -l` (+ `id -un`) | Персональный crontab **SSH-пользователя** (того, под кем подключились). Если вошли как root — это crontab **root**, не других |
| `systemCrontab` | `cat /etc/crontab` | Системный `/etc/crontab` (read-only) |
| `cronD` | `cat /etc/cron.d/*` | Системные `/etc/cron.d/*` (read-only) |

**Ключевые выводы:**
- Персональные crontab'ы других пользователей (`/var/spool/cron/crontabs/<user>`,
  `/var/spool/cron/<user>`) **не перечисляются** — скан-а по пользователям нет.
- Поле `user` у задачи появляется **только в системных файлах**
  (`/etc/crontab`, `/etc/cron.d/*`) — это «от чьего имени выполняется задача»,
  а НЕ персональный crontab юзера.
- Мутации — **только своего** crontab: `crontab -` с защитой от гонки
  `expectedRaw` (409 при расхождении). Системные файлы — read-only.

### Ключевые места кода
- `server/src/services/cron.ts` — вся логика:
  - `fetchUserCrontab` (строки 273–280): `crontab -l 2>/dev/null`; exit 1 + пусто → null.
  - `fetchSystemCron` (строки 283–303): `=== /etc/crontab` / `=== /etc/cron.d/*` маркерами.
  - `collectCron` (324–338) — кэш 2 с на профиль.
  - `mutateUserCrontab` (344–353): перечитать → `applyCrontabOp` → `crontab -` stdin.
  - `parseCrontab` / `parseCronLine` (112–140): `system:true` добавляет колонку `user`.
  - `CronOp` (41–45): add/update/delete/toggle, update/delete/toggle требуют `expectedRaw`.
- `server/src/routes/cron.ts` — эндпоинты `/api/cron`, `/api/cron/entries[/:index]`.
- `web/src/pages/CronPage.tsx` — вкладка (сейчас в старой стилистике).
- `web/src/api.ts` — `CronEntry`, `ParsedCrontab`, `CronSnapshot`, `fetchCron`,
  `addCronEntry`, `updateCronEntry`, `deleteCronEntry`, `toggleCronEntry`.

## 3. Что хотим: перечисление crontab всех пользователей (под root)

**Идея:** дать возможность при root видеть (и, по желанию, править) crontab
всех пользователей, а не только своего.

### Открытые вопросы — решить до реализации
1. **Способ перечисления пользователей**: читать `getent passwd` / `/etc/passwd`
   (просто), либо сканировать сам spool-каталог (видно только тех, у кого есть
   crontab — чище). Может, комбинировать: список из passwd, а «есть ли crontab»
   — по наличию spool-файла.
2. **Путь spool-каталога зависит от дистрибутива** (нужна детекция/фолбэк):
   - Debian/Ubuntu (vixie-cron): `/var/spool/cron/crontabs/<user>`
   - cronie (RHEL/Fedora/Arch): `/var/spool/cron/<user>`
   - BusyBox/прочие — ещё варианты.
   Это классическая ловушка «путь к crontab разный» — не захардкодить один.
3. **Читать как**: `crontab -u <user> -l` (правильный путь, `-l` с `-u`),
   vs чтение spool-файла напрямую (`cat`). `crontab -u <user> -l` корректнее
   (учитывает пробелы/комментарии, как их видит cron), но требует, чтобы `crontab`
   поддерживал `-u` (есть у cronie/vixie). Чтение файла напрямую — фолбэк.
4. **Права**: читать чужие spool-файлы может только root/через sudo. Не-root —
   либо отказ, либо sudo. Согласен ли пользователь на sudo для чтения чужих.
5. **Мутации** (add/update/delete/toggle) чужих crontab: только root, через
   `crontab -u <user> -` (stdin) — это расширяет `CronOp` на `user`, ломает
   инвариант «только свой crontab». Нужно явное решение: править можно только
   свои, а чужие — read-only (безопаснее), или добавлять sudo-подтверждение.
6. **UI**: как показать выбор пользователя — выпадающий список над списком задач?
   Только для root? Секция «Пользователи»?
7. **Детект systemd-принадлежности / какую крон-реализацию** использовать для
   команды `crontab -u`.

### Предлагаемая реализация (черновик, до подтверждения)
- Сервер: новый `GET /api/cron/users?profileId=` → список юзеров с флагом
  `hasCrontab`. Детект spool-пути (по `command -v crontab` + дистрибутив/попытка
  обоих путей). Чтение каждого: `crontab -u <user> -l` (фолбэк — `cat` spool-файла).
- Расширить `CronSnapshot`: либо `{user, crontab}` для выбранного юзера, либо
  отдельные эндпоинты `GET /api/cron/:user`.
- Мутации: оставить только для текущего SSH-юзера (безопасно), чужие —
  read-only. Если нужна правка чужих — отдельный toggle с sudo (по образцу
  эпика 13 systemd: общий `services/sudo.ts`).
- Кэш 2 с (как у портов/метрик); `expectedRaw`-защита сохраняется.
